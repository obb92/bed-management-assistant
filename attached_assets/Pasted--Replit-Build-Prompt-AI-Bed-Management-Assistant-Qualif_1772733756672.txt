## PASTE THIS ENTIRE PROMPT INTO REPLIT AGENT

---

Build a single-page React application called **CareFlow** — an AI-powered bed management assistant for hospital Bed Coordinators and Charge Nurses. This is a demo-ready prototype for a case interview presentation. It must look polished, work reliably, and showcase generative AI recommendations in a real hospital operations context.

---

## TECH STACK

- **Frontend:** React (single file or component-based, your choice — but keep it simple)
- **Styling:** Tailwind CSS
- **AI Layer:** Anthropic Claude API (`claude-sonnet-4-20250514`) via `fetch` calls to `https://api.anthropic.com/v1/messages`
- **No backend required.** All data is hardcoded synthetic state. API key is injected via Replit Secrets as `ANTHROPIC_API_KEY` — read it from `process.env.ANTHROPIC_API_KEY` or `import.meta.env.VITE_ANTHROPIC_API_KEY` depending on the Replit setup.
- **No database, no auth backend.** Login is cosmetic — clicking login proceeds directly to the app.

## APP STRUCTURE

### Global State
The app holds one of two synthetic data states in memory: **TC1 (2am Crunch)** or **TC2 (Morning Surge)**. The active scenario determines all data shown across every screen. State also tracks:
- `activePersona`: "coordinator" or "nurse"
- `activeFloor`: "3 South" or "4 North" (only relevant when persona = nurse)
- `activeScenario`: "TC1" or "TC2"
- `actionCardStates`: object tracking Done/Snoozed/Flagged status of each action card
- `demoMode`: boolean
- `demoStep`: integer (1–6)

## IMPORTANT IMPLEMENTATION NOTES

1. **The AI chat must work live.** Every message must hit the real Claude API with the full system prompt including scenario data. Do not mock the chat responses.

2. **All other AI content (briefings, action cards) is hardcoded.** Do not call the API for briefings or action cards — use the exact text from the DATA LAYER above. This ensures demo reliability.

3. **The feedback loop is pure React state.** When the Nurse hits Confirm or Flag, update the shared state object. The Coordinator's view re-renders from that state. No API call needed for this.

4. **Pre-fill the TC2 chat input.** When TC2 is active and the user navigates to Ask AI, pre-populate the input with: *"If 412 doesn't clear by 10:30, what are my options for the surgical admit?"* — editable, not locked.

5. **Scenario switching resets all state** (action card states, flag text, chat history) except the active persona.

6. **Keep the app to one page with React state managing navigation.** No React Router needed.

7. **Do not show a loading spinner for action cards or briefings** — they are hardcoded and should appear instantly.

8. **Show a typing indicator for the AI chat** while waiting for the API response.

9. **The bed board animation** (amber→pulsing when housekeeping dispatched) should trigger when Card 1 in TC1 is marked Done, regardless of which screen the user is on. When they navigate to Beds, the animation should already be running.

10. **Error handling for the API:** If the Claude API call fails, show a subtle error message in the chat: "Unable to reach AI — check your API key in Replit Secrets." Do not crash the app.
